## API options investigated (9 September 2026)

1. Prompt: conversational answers2–4sentences/one optional question, explicit language and distinction unreported emotion vs absence. Better target than generic long analysis instructions. Test before claiming gains.
2. Thinking: current low is verified. Official thinking table now lists minimal/low/medium/high for3.5Lite, conflicting with the adapter's prior compatibility rule that promotes minimal to low. Probe actual support separately before changing.3.8supports low/medium/high only. More thinking need not improve factual fidelity.
3. max_output_tokens: current2048 is a ceiling, not a desired length. A lower ceiling can truncate; prefer concise instructions before testing512–768. No guaranteed first-text improvement.
4. History: preserve exact user associations/corrections with provenance, alongside recent exchanges. Do not let assistant-generated summaries become facts. Current20-message cap keeps costs bounded but does not preserve20complete exchanges.
5. Streaming: already enabled, improves progressive display; cannot remove reasoning before first answer text.
6. Implicit caching: available automatically in Interactions; stable common prefix helps cache hits. Explicit cache objects unsupported on Interactions. This run had zero cache hits; no savings claimed.
7. Priority service tier: prioritizes requests for higher price; no semantic quality gain or guaranteed measured speedup. Standard remains sensible for~2seconds. Flex/Batch trade latency for lower cost and are unsuitable for immediate chat.
8. previous_interaction_id: server-stored continuation conflicts with store:false; not adopted. It is not proof of token billing savings.
9. Structured JSON: useful for analysis shape, not semantic truth. No temperature/top-p tuning proposal for3.8 because its migration guide removes those sampling parameters.
