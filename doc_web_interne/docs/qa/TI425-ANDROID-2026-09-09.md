## Construction et installation

Node `24.19.0`, npm `11.17.0`, Expo `57.0.17`. `npm ci` depuis le lockfile du candidat réussit. `expo prebuild --platform android --no-install` réussit ; génération native autorisée par la demande explicite Expo run Android.

Compilation locale `./gradlew app:assembleDebug -x lint -x test --build-cache -PreactNativeDevServerPort=8081 -PreactNativeArchitectures=arm64-v8a` avec JDK 17 : **BUILD SUCCESSFUL en 3 min 38 s**, 739 tâches. Cela ne constitue pas une suite de tests applicatifs.

Les certificats différents interdisaient un remplacement direct. Après la demande explicite de désinstaller l’actuelle, `adb uninstall com.tanuki75.noctalia` réussit ; seule cette application a été désinstallée, avec son état local. Installation et lancement réussis par la commande canonique :

```sh
ANDROID_SERIAL=<Motorola> ADB_SERVER_SOCKET=tcp:localhost:5038 \
ADB_BIN=<SDK>/platform-tools/adb JAVA_HOME=<JDK17> ANDROID_HOME=<SDK> \
EXPO_NO_DOTENV=1 NOCTALIA_DREAMER_QA_BUILD=0 \
NOCTALIA_APP_VARIANT=noctalia EXPO_PUBLIC_APP_VARIANT=noctalia \
NODE_OPTIONS=--dns-result-order=ipv4first \
npm run android -- --binary android/app/build/outputs/apk/debug/app-debug.apk
```

L’option Expo `--device` attend un nom ; le runner de verrou attend un identifiant ADB. `ANDROID_SERIAL` cible explicitement le Motorola, seul appareil présent dans le serveur ADB isolé. Une première invocation avec le numéro ADB dans `--device` a échoué avant installation ; aucun changement de code pour contourner cette différence.

## Environnement, limites et remise en état

- ADB partagé sur 5037 ne pouvait pas joindre le téléphone alors que le test TCP de l’endpoint fourni réussissait. Un serveur ADB séparé sur 5038, lancé hors sandbox, a connecté le Motorola. Aucun `adb kill-server` ni interruption des autres transports.
- Verrou hôte partagé acquis pour les préflights, remplacement et lancement. Le runner canonique l’a conservé pendant la QA ; libération vérifiée à sa sortie. Les dernières opérations ont utilisé de courts verrous, tous libérés.
- Un ancien réglage Android `debug_app=com.tanuki75.noctalia`, `wait_for_debugger=1` bloquait le premier lancement sur « Waiting For Debugger ». Il a été désactivé avec `am clear-debug-app` et laissé désactivé pour que la version demandée puisse démarrer.
- Police remise à `1.0`, services d’accessibilité remis à `null`, accessibilité à `0`, valeurs vérifiées identiques à l’état initial. Aucune dictée lancée, permission micro demandée, connexion de compte ou transaction.
- La bulle Tools visible en haut à droite appartient au client de développement Expo ; elle recouvre partiellement certains contrôles de l’en-tête dans les captures. L’accès Paramètres a été vérifié hors de cette bulle. Ce n’est pas une preuve du rendu Release.
- Le runtime sans profil secret ne configure pas Google Sign-In ni Play Integrity ; ces parcours n’ont pas été testés.
- Auto-review a refusé de laisser Metro exposé en LAN après le test. Alternative plus limitée acceptée : `npm run start -- --port 8081 --localhost`, écoute `127.0.0.1:8081` vérifiée, transfert `adb reverse tcp:8081 tcp:8081` sur le seul Motorola. Serveur conservé pour permettre à l’utilisateur de poursuivre le test local. Aucun verrou appareil conservé.
- Lors de la dernière vérification après passage de Metro à localhost, le téléphone affichait l’application Appareil photo, indiquant une reprise d’usage externe. Les interactions ont été arrêtées ; la capture hors Noctalia a été supprimée. Le dernier écran Noctalia attesté est Explorer avant ce changement de Metro, sans promesse sur l’écran actuellement au premier plan.
- Aucun source produit modifié, aucun commit, push, EAS, Store, déploiement ou accès à des rêves personnels. `git diff --check` réussi pour le rapport.
