# TI-522 local import foundation

This is a preparatory engine, not an enabled import feature. No screen, consent UI, RPC client, native OAuth setup or provider is wired. Remote activation depends on TI-560's scoped authentication rollout. The confirmation object is an application contract, not proof of server authorization; the eventual reader must authenticate the source account and verify the grant server-side on every page.

The pure engine accepts the TI-560 paginated item/page shape and an explicitly confirmed grant, source account and destination scope. It projects only source identity/revision, date and transcript into local copies. Media, analysis and health fields are discarded. Copies live under `noctalia_lucid_journal_copies`, outside trainer state and its cloud queue. There is no Journal mutation or shared global provider dependency.

A serialized operation encodes copies and the resume cursor into immutable protected chunks, then atomically publishes one small manifest. The v2 storage protocol writes a protected pending-generation journal before any chunk. Recovery removes only inactive generations named by that journal, preserving the active manifest and all foreign scopes. Chunk and manifest failures leave the previous snapshot readable; an acknowledgement error after a committed manifest is resolved by reloading the actual durable manifest. Writes and recovery reads are serialized per destination across adapter instances. Failed reads do not become empty data. Failed writes do not advance the engine's acknowledged cursor; retry reloads actual durable state. Repeated grants resume or return their completed checkpoint; fresh grants deduplicate by product/account/source ID. Local edits produce explicit conflicts, resolved through keepLocal/useIncoming. Deletion clears copied text and retains a tombstone preventing resurrection. No dream signs are generated.

Generation, destination and source checks surround asynchronous import work. Cancel/account changes prevent subsequent reads/writes and reject stale results. An already-issued atomic OS storage write cannot be cancelled; it can finish only in its captured original namespace, never the new account. Integrators must call cancel on authentication transitions, including A→B→A changes that occur entirely between asynchronous checks. A single engine instance owns each destination namespace; concurrent independent instances are not supported.

The native adapter reuses the existing AES-GCM device key with each scoped chunk/manifest key as authenticated data and rejects unprotected native values. Web retains the existing plaintext storage policy. Chunks contain at most 128,000 UTF-16 code units and never split a surrogate pair, staying below the existing per-value encryption capacity. There is no 1.5MB total snapshot ceiling. The adapter test round-trips 2,501 realistic Unicode transcripts exceeding that size under a mocked crypto capacity limit. Total storage and memory remain finite: snapshots are still materialized and rewritten per page, and no unlimited-size or device-performance guarantee is claimed. This unpublished v2 protocol does not migrate the unpublished v1 prototype.

Nineteen focused deterministic tests cover 0/1/2,501 entries, cancellation/source/destination switches during reads, storage/read failures and durable resume, deduplication, local conflicts, tombstones, grant expiry and strict field projection. Native encryption/device behavior and a real scoped RPC are not qualified here.

## Scoped RPC reader preparation

`createLucidJournalImportReader` is an unwired adapter for the actual `read_journal_import_page(p_cursor, p_limit)` contract in migration `20260909020000_journal_import_grants.sql`. It accepts an already explicitly confirmed grant plus an authenticated client and session authority supplied by the session owner. The authority must come from the scoped authentication integration, never a user-editable product header or metadata. No token is decoded or OAuth session created here. The server remains responsible for cryptographic identity, registered clients, consent expiry/revocation and cursor ownership.

The reader requires the source account to match the authenticated owner, the registered destination client and local destination scope to match confirmation, and the session generation to remain unchanged across each RPC. The session owner must increment that generation on every authentication transition, including A→B→A. Request parameter names are exactly snake_case; response fields are exactly the server's camelCase contract. Decimal IDs/revisions remain strings. Denials and malformed data throw, never become an empty journal or trigger direct table access. Only transcript/date/identity fields leave the adapter.

Seventeen additional reader tests cover opaque pagination, exact mapping, denied/malformed results, source/destination/client changes, expiry and generation changes. These use an injected RPC stub; no claim is made that an OAuth client or deployed migration is active. Runtime consent UI and real scoped client wiring remain pending.
